# GLM 角色分流

派发子任务时按下面的规则选角色。两个角色由插件 glm-roles 提供：子代理类型为 `glm-roles:deep` 和 `glm-roles:flash`，各自的模型和思考等级已在角色定义里固定，派发时不要再指定 model。

## 用 flash（GLM-5.3-Flash，快而省）——默认选择

- 搜集信息、查定义、找文件、统计
- 简单查询和总结
- 明确的单文件小改动、重命名、格式化
- 批量重复的机械修改

## 用 deep（GLM-5.3，深思考）——需要动脑才用

- 方案设计与架构权衡
- 跨多文件的复杂实现或重构
- 疑难 bug 的根因分析
- 核心算法实现、代码审查、安全相关分析

## 规则

- 简单任务默认派 flash；只有确实需要深思考才派 deep，避免浪费。
- 派发消息必须自包含：目标、上下文、相关路径、验收标准。
- 主对话模型不归本插件管：由用户在界面选择，不要试图替用户切换主模型。
- 角色的模型是可指派的槽位：`agents/*.md` 的 `model:` 可以填任何当前登录可见套餐下的模型（形如 `account:<套餐>/<模型>`），跨套餐混搭没问题。用户问"有哪些模型可选"时用 ListModels 查询并按套餐分组展示；要改绑定时引导用 `/glm-roles:assign <角色> <模型ID>`。
- 如果 `glm-roles:deep` / `glm-roles:flash` 这两个子代理类型不存在（插件未安装或未启用），不要报错中断：改用默认子代理完成任务，并在回复里提一句插件不可用。
- 如果派发某个角色失败且原因疑似其绑定的模型不可用（套餐变更、模型下线等），不要反复重试：回退用默认子代理完成任务，并提示用户用 `/glm-roles:models` 核对后重新指派。
